## Что делает скрипт

| Шаг | Действие | Файл / сервис |
| :--- | :--- | :--- |
| **0** | Проверки: sshd, systemctl, authorized_keys, порт, имя пользователя | — |
| **1** | Бэкап `sshd_config`, правил ufw, `jail.local`, sysctl | `/root/.ssh-hardening-backup-<дата>/` |
| **2** | Создание `pilot` + sudo | `useradd`, `usermod` |
| **3** | Копирование SSH-ключей из root в `~pilot/.ssh/authorized_keys` | `cp`, `chmod 600`, `chown` |
| **4** | Харденинг `sshd_config` (порт, отключение root/password auth, `AllowTcpForwarding yes` для туннеля 3x-ui) | `/etc/ssh/sshd_config` |
| **5** | Проверка синтаксиса + перезапуск SSH (с авто-откатом при ошибке) | `sshd -t`, `systemctl restart ssh` |
| **6** | fail2ban с `bantime 1h`, `maxretry 3`, `banaction ufw` | `/etc/fail2ban/jail.local` |
| **7** | ufw: deny incoming / allow outgoing / allow SSH-порт | `ufw` |
| **8** | Автообновления безопасности | `/etc/apt/apt.conf.d/20auto-upgrades` |
| **9** | sysctl: BBR, буферы, защита (как в шаге 1.3.10) | `/etc/sysctl.d/99-claude-proxy.conf` |
| **10** | Проверка часового пояса (информативно) | `timedatectl` |

## Встроенные защиты от блокировки доступа

| Механизм | Что делает |
| :--- | :--- |
| **Проверка `authorized_keys` root** | Скрипт не запустится, если у root нет ключей |
| **Бэкап до изменений** | Полный бэкап в `/root/.ssh-hardening-backup-<дата>/` |
| **`sshd -t` перед применением** | Синтаксическая проверка нового конфига |
| **Проверка после применения** | `sshd -t` после записи — при провале авто-откат |
| **`--dry-run`** | Показать всё без изменений |
| **`--rollback`** | Восстановить из последнего бэкапа |
| **Интерактивное подтверждение** | Требует ввести `YES` перед изменениями |
| **Открытие нового порта до перезапуска** | ufw получает правило для нового порта до `systemctl restart ssh` |
| **Напоминание про VNC/KVM** | После завершения скрипт требует проверить доступ в новом терминале |

## Использование

```bash
# 1. Сделать исполняемым
chmod +x setup-ssh.sh

# 2. Пробный прогон (ничего не изменится)
sudo ./setup-ssh.sh --dry-run

# 3. Реальный запуск с параметрами по умолчанию (порт 1337, пользователь pilot)
sudo ./setup-ssh.sh

# 4. Свои параметры
sudo ./setup-ssh.sh --port 2222 --user admin

# 5. Пропустить отдельные компоненты
sudo ./setup-ssh.sh --skip-firewall --skip-fail2ban

# 6. Откат при проблемах
sudo ./setup-ssh.sh --rollback
```

## Порядок безопасного запуска (рекомендуется)

1. **Скопируйте SSH-ключ на сервер** (из вашего ПК):
   ```bash
   ssh-copy-id -i ~/.ssh/id_ed25519_claude.pub root@<IP>
   ```
2. **Проверьте, что ключ работает** — не закрывая root-сессию, откройте новый терминал и войдите по ключу.
3. **Запустите `--dry-run`** — просмотрите план.
4. **Запустите реальный прогон** — подтвердите `YES`.
5. **НЕ ЗАКРЫВАЙТЕ текущую root-сессию** — откройте новый терминал и проверьте:
   ```bash
   ssh -p 1337 -i ~/.ssh/id_ed25519_claude pilot@<IP>
   ```
6. Только после успешного входа — закройте старую сессию.

## Exit codes

| Код | Значение |
| :---: | :--- |
| `0` | Успех / dry-run / rollback |
| `2` | Критическая ошибка (нет ключей, sshd не запустился, откат) |
| `3` | Ошибка аргументов / окружения |

## Что скрипт **не** делает

- ❌ **Не создаёт** новый SSH-ключ (нужно сгенерировать на ПК заранее).
- ❌ **Не копирует** ключ с ПК на сервер автоматически (используйте `ssh-copy-id` до запуска).
- ❌ **Не меняет** часовой пояс автоматически (только предупреждает).
- ❌ **Не настраивает** 3x-ui — это шаг 1.4 в `vps-setup.md`.

## 🗺️ Архитектура решения

| Компонент | Где размещать | Роль в схеме |
| :--- | :--- | :--- |
| **VPS (3x-ui + Xray)** | Европа / США | Единственная «точка выхода» в интернет, которую видит Anthropic |
| **Клиент VLESS (v2rayN / Hiddify)** | Ваш ПК | Поднимает локальный SOCKS5/HTTP-прокси, туннелирующий трафик до VPS |
| **Dolphin{anty}** | Ваш ПК | Изолированный браузерный профиль с подменой timezone / language / WebRTC под IP VPS |
| **Claude Desktop** | Ваш ПК | Electron-приложение, читает системный прокси или `egressProxyUrl` |
| **Claude Code (CLI)** | Ваш ПК | Node.js CLI, читает `HTTPS_PROXY`, **не поддерживает SOCKS** |
| **VS Code** | Ваш ПК | Настройка `http.proxy` в `settings.json` |
| **Cursor IDE** | Ваш ПК | `http.proxy` + принудительное отключение HTTP/2 |
| **LM Studio** | ПК (GUI) **или** VPS (headless) | Локальный инференс; headless-режим на VPS — опционально |
| **Gemini CLI / Codex CLI** | Ваш ПК | Читают `HTTPS_PROXY` / `HTTP_PROXY`; Codex дополнительно `CODEX_CA_CERTIFICATE` |

### Принципиальная схема

```
┌──────────────────────────────────────────────────────────────────┐
│                        Ваш ПК                                    │
│                                                                  │
│  ┌───────────────┐  ┌────────────┐  ┌────────────────────────┐   │
│  │ Claude Desktop│  │ Claude Code│  │ VS Code / Cursor / CLI │   │
│  └───────┬───────┘  └─────┬──────┘  └────────────┬───────────┘   │
│          │                │                      │               │
│          └────────────────┼──────────────────────┘               │
│                           ▼                                      │
│                ┌──────────────────────┐                          │
│                │  Локальный прокси    │  HTTP  :10809            │
│                │  (v2rayN / Hiddify)  │  SOCKS :10808            │
│                └──────────┬───────────┘                          │
└───────────────────────────┼──────────────────────────────────────┘
                            │  VLESS + Reality (TLS 1.3)
                            ▼
             ┌──────────────────────────────┐
             │  VPS (Европа / США)          │
             │  3x-ui + Xray                │
             │  Inbound :443 → Reality      │
             │  Outbound → Anthropic API    │
             └──────────────┬───────────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │  api.anthropic.com  │
                 │  claude.ai          │
                 └─────────────────────┘
```

> **Ключевой принцип:** сам VPS — это только «шлюз». Все приложения-клиенты остаются на вашем ПК, но их сетевой трафик перенаправляется на VPS через локальный прокси.

## 🖥️ Часть 1. Настройка VPS-сервера

### Шаг 1.1. Выбор конфигурации и провайдера

Для роли прокси-шлюза **не требуется высокая производительность**. Трафик к Claude — это HTTPS-запросы и SSE-стриминг ответов; нагрузка на CPU минимальна.

**Рекомендуемая конфигурация:**

| Параметр | Минимум | Рекомендуется |
| :--- | :--- | :--- |
| **vCPU** | 1 | 1 (x86_64 или ARM) |
| **RAM** | 1 GB | 2 GB (с запасом под WARP) |
| **Диск** | 20 GB | 30 GB SSD/NVMe |
| **IPv4** | Статический — **обязателен** | Статический |

> **Почему IPv4 обязателен:** Anthropic и промежуточные CDN могут не иметь AAAA-записей для всех эндпоинтов. IPv6-only не подходит.

**Локация.** Выбирайте страну, где Anthropic официально предоставляет сервис:

- 🇺🇸 США
- 🇩🇪 Германия
- 🇳🇱 Нидерланды
- 🇬🇧 Великобритания

> **Избегайте** локаций, которые сами по себе являются «красным флагом» для антифрода (некоторые хостинги в странах с высокой долей abuse-трафика).

**Требование к провайдеру:** возможность **пересоздания сервера с выдачей нового IP** без дополнительной платы — это понадобится на следующем шаге.

---

### Шаг 1.2. Проверка «чистоты» IP-адреса (критический этап)

Сразу после получения сервера, **до установки какого-либо ПО**, проверьте IP на [`scamalytics.com`](https://scamalytics.com).

| Fraud Score | Интерпретация | Действие |
| :--- | :--- | :--- |
| **0–30** | Низкий риск | ✅ Продолжайте |
| **30–74** | Средний риск | ⚠️ Допустимо, но мониторьте |
| **75–100** | Высокий риск | ❌ **Немедленно пересоздайте сервер** |

**Дополнительные проверки:**

- [`ipinfo.io`](https://ipinfo.io) — тип `hosting` / `datacenter` — нормально.
- [`multirbl.valli.org`](https://multirbl.valli.org) — убедитесь, что IP не числится в публичных DNSBL.

> «Чистый» IP дата-центра сам по себе **не является** триггером для Anthropic. Триггером является история abuse и несоответствие отпечатка.

---

### Шаг 1.3. Базовая подготовка системы (до установки 3x-ui)

Подключитесь по SSH и выполните **минимум** следующие действия:

```bash
# Обновление системы
sudo apt update && sudo apt upgrade -y && sudo apt autoremove -y

# Смена пароля root (если хостинг выдал автоматический)
passwd

# Создание отдельного пользователя (рекомендуется)
useradd -m -s /bin/bash pilot
passwd pilot
usermod -aG sudo pilot
```

**Настройка SSH** — откройте `/etc/ssh/sshd_config` и приведите ключевые параметры к виду:

```ini
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
Port 1337          # нестандартный порт
ClientAliveInterval 60
ClientAliveCountMax 720
```

> ⚠️ **Перед перезапуском SSH** добавьте свой публичный SSH-ключ в `~/.ssh/authorized_keys` пользователя `pilot`, иначе потеряете доступ.

**Firewall** — активируйте `ufw` и разрешите только SSH и будущий порт панели 3x-ui:

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 1337/tcp        # ваш SSH-порт
sudo ufw allow 2053/tcp        # порт панели 3x-ui (по умолчанию)
sudo ufw enable
sudo ufw status verbose
```

### Шаг 1.4. Установка 3x-ui

Выполните установку одной командой:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

Скрипт запросит параметры администратора. **Сразу смените логин и пароль по умолчанию** — панель доступна по HTTP на `http://<IP>:2053`, и стандартные учётные данные известны всем.

> 🔒 **Важно:** панель 3x-ui слушает HTTP. Не оставляйте её открытой в интернет дольше, чем необходимо. После настройки inbound закройте порт `2053` в `ufw` и подключайтесь к панели через SSH-туннель:
>
> ```bash
> ssh -L 2053:127.0.0.1:2053 pilot@<IP_VPS>
> ```

### Шаг 1.5. Создание inbound VLESS + Reality

В панели 3x-ui перейдите в **Inbounds → Add Inbound** и заполните:

| Параметр | Значение |
| :--- | :--- |
| **Protocol** | `vless` |
| **Port** | `443` |
| **Security** | `reality` |
| **Flow** | `xtls-rprx-vision` |
| **Dest** | `www.microsoft.com:443` (или `www.apple.com:443`, `www.wikipedia.org:443`) |
| **Server Names** | тот же домен, что в `Dest` |
| **Short IDs** | сгенерируйте 2–3 случайных значения кнопкой Generate |

**Почему Reality, а не обычный TLS:** Reality не требует собственного домена и сертификата; он «одалживает» TLS-хендшейк реального популярного сайта, что делает трафик неотличимым от обычного HTTPS к выбранному домену при пассивном DPI. `xtls-rprx-vision` дополнительно снижает характерные тайминговые паттерны TLS-in-TLS.

**Требования к `Dest`:**

1. ✅ Доступен с вашего VPS (проверьте `curl -I https://www.microsoft.com` с сервера);
2. ✅ Популярен (высокий трафик к нему не выглядит аномалией);
3. ✅ Поддерживает TLS 1.3 и HTTP/2 (большинство крупных CDN поддерживают).

Сохраните inbound. Панель сгенерирует **ссылку вида `vless://...`** — скопируйте её. Она понадобится на стороне ПК.

### Шаг 1.6. (Опционально) WARP для дополнительной маскировки исходящего трафика

Если вы хотите, чтобы **исходящий** трафик с VPS к Anthropic шёл не напрямую с IP вашего хостинга, а через Cloudflare WARP, настройте Outbound в 3x-ui.

**Пошагово:**

1. Установите WARP на VPS.
2. Переведите его в режим SOCKS5-прокси:
   ```bash
   warp-cli mode proxy
   ```
   Слушает `127.0.0.1:40000`.
3. В 3x-ui → **Xray Settings → Outbound** добавьте исходящее подключение:
   - Протокол: `socks`
   - Адрес: `127.0.0.1`
   - Порт: `40000`
4. Маршрутизируйте через него только нужные домены (или весь трафик — по желанию).

> ⚠️ **Предупреждение:** при использовании `warp-cli` в режиме `proxy` существует потенциальная утечка реального IP VPS по UDP. Если это критично, используйте альтернативу через Dante-прокси.

## 💻 Часть 2. Настройка Вашего ПК

### Шаг 2.1. Установка клиента VLESS

На ПК установите один из клиентов:

- **v2rayN** (Windows, наиболее распространён)
- **Hiddify** (кроссплатформенный)

Импортируйте ссылку `vless://...`, сгенерированную на шаге 1.5, через **«Импорт из буфера обмена»**. Активируйте профиль.

**Режим работы клиента — критически важен:**

| Режим | Плюсы | Минусы |
| :--- | :--- | :--- |
| **Системный прокси** *(рекомендуется для начала)* | Работает для большинства приложений; не требует прав администратора | Некоторые приложения игнорируют системный прокси |
| **TUN-режим** | Перехватывает **весь** трафик на уровне ОС | Может конфликтовать с корпоративными VPN; требует прав администратора |

> Для схемы с Claude **начните с системного прокси** — этого достаточно для большинства инструментов. TUN оставьте как запасной вариант.

**Обязательные настройки против утечек** (в v2rayN / Hiddify):

- ✅ включите **Remote DNS** (DNS-запросы уходят через туннель, а не через вашего провайдера);
- ✅ включите **блокировку WebRTC** (если опция есть);
- ✅ в правилах маршрутизации убедитесь, что `claude.ai`, `anthropic.com`, `cursor.sh`, `openai.com` (для Codex) и домены Gemini идут через прокси.

---

### Шаг 2.2. Настройка антидетект-браузера Dolphin{anty}

Веб-версия `claude.ai` в обычном браузере — **худший** вариант с точки зрения обнаружения: браузер сообщает реальный timezone ОС, язык системы, разрешение экрана и, главное, может «сливать» локальный IP через WebRTC. Антидетект-браузер решает эту проблему.

**Пошагово:**

1. Установите [Dolphin{anty}](https://dolphin-anty.com) и создайте **новый профиль**.
2. В разделе **Proxy** укажите:
   - Тип: `socks5` или `http`
   - Хост: `127.0.0.1`
   - Порт: `10808` (SOCKS5) или `10809` (HTTP) — порт вашего локального клиента
   > ❗ **Не** указывайте IP VPS напрямую — трафик должен идти через локальный клиент, который уже туннелирует его до VPS.
3. В разделе **Advanced / Fingerprint** установите:
   | Параметр | Значение |
   | :--- | :--- |
   | **Timezone** | `Auto` (подтянется по IP прокси) |
   | **Language** | `Auto` (соответствует локали IP) |
   | **Geolocation** | `Auto` |
   | **WebRTC** | `Altered` (или `Disabled`) |
4. Сохраните профиль, запустите его и **немедленно проверьте** [`ipleak.net`](https://ipleak.net):
   - IP = IP вашего VPS ✅
   - Timezone и language соответствуют выбранной стране ✅
   - WebRTC не показывает из вашей страны IP ✅

> **Правило гигиены:** используйте этот профиль **только** для Claude и связанных AI-сервисов. Не логиньтесь в нём в вашей страны сервисы (почта, соцсети) — это создаст «склейку» между вашей страны и «иностранным» цифровыми следами и сведёт на нет всю маскировку.

---

### Шаг 2.3. Настройка системных переменных окружения (Windows)

Большинство CLI-инструментов (Claude Code, Gemini CLI, Codex CLI) читают стандартные переменные `HTTP_PROXY` / `HTTPS_PROXY`. Установите их **на уровне пользователя**, чтобы не затрагивать системные настройки:

```powershell
# PowerShell (не требует прав администратора для уровня User)
[System.Environment]::SetEnvironmentVariable("HTTP_PROXY",  "http://127.0.0.1:10809", "User")
[System.Environment]::SetEnvironmentVariable("HTTPS_PROXY", "http://127.0.0.1:10809", "User")
[System.Environment]::SetEnvironmentVariable("NO_PROXY",    "localhost,127.0.0.1,::1", "User")
```

> **Порт `10809`** — пример порта HTTP-прокси v2rayN. Замените на **фактический** порт вашего клиента.

**Проверка:**

```bash
curl -x http://127.0.0.1:10809 https://api.anthropic.com
```

Должен вернуть ответ (даже ошибку авторизации — главное, что соединение установлено).

> 🔴 **Для Claude Code критично:** он **не поддерживает SOCKS-прокси** — только `http://` и `https://`. Если ваш клиент предоставляет только SOCKS5, настройте в нём HTTP-прокси (v2rayN умеет поднимать оба одновременно) или используйте локальный конвертер (например, `privoxy`).

### Шаг 2.4. Проверка отсутствия утечек

Перед первым входом в Claude выполните три проверки:

| № | Проверка | Инструмент | Ожидаемый результат |
| :--- | :--- | :--- | :--- |
| 1 | **IP** | [`ipleak.net`](https://ipleak.net) в антидетект-профиле | Только IP VPS |
| 2 | **DNS** | [`ipleak.net`](https://ipleak.net) → DNS | Не из вашей страны DNS |
| 3 | **WebRTC** | [`browserleaks.com/webrtc`](https://browserleaks.com/webrtc) | Публичный IP отсутствует или = IP VPS |

> ❌ Публичный из вашей страны IP в WebRTC — **недопустим**.
> ✅ Локальные IP (`192.168.x.x`) допустимы.

## ⚙️ Часть 3. Настройка конкретных инструментов

### 3.1. Claude Desktop

Claude Desktop — **Electron-приложение**, и его поведение с прокси неоднородно: разные части продукта (само окно, движок Claude Code, песочница Cowork) резолвят прокси по-разному.

#### Вариант А — системный прокси (проще)

По умолчанию приложение следует настройкам прокси ОС, включая PAC-скрипты. Если ваш клиент VLESS работает в режиме «Системный прокси», Claude Desktop **скорее всего** подхватит его автоматически.

> ⚠️ Однако агент (движок Claude Code внутри Desktop) не читает настройки ОС напрямую: при старте сессии приложение спрашивает ОС, какой прокси применим к inference-эндпоинту, и передаёт агенту результат как `HTTPS_PROXY` / `HTTP_PROXY`. Если ОС возвращает SOCKS-прокси, приложение его **пропускает**, и агент подключается напрямую. Поэтому для Desktop **системный прокси должен быть HTTP/HTTPS, а не SOCKS**.

#### Вариант Б — принудительное закрепление прокси через реестр (надёжнее)

На Windows Claude Desktop читает `egressProxyUrl` из ветки `HKLM\SOFTWARE\Policies\Claude` (REG_SZ):

```powershell
# PowerShell от имени администратора
New-Item -Path "HKLM:\SOFTWARE\Policies\Claude" -Force
Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Claude" `
                 -Name "egressProxyUrl" `
                 -Value "http://127.0.0.1:10809" `
                 -Type String
```

Это заставит **и приложение, и агент** использовать указанный HTTP-прокси независимо от системных настроек.

> ⚠️ **Ограничение:** интерактивная аутентификация прокси не поддерживается — ваш локальный прокси не должен требовать логин/пароль (v2rayN в режиме локального прокси обычно не требует).

> 🔒 **Про TLS-инспекцию:** если ваш прокси выполняет TLS-инспекцию (подменяет сертификаты), Claude Desktop может отказаться работать. Для локального VLESS-клиента TLS-инспекции нет — сертификаты end-to-end, проблема не возникает.

### 3.2. Claude Code (CLI)

Claude Code — Node.js CLI. Читает стандартные переменные в порядке приоритета:

```
https_proxy → HTTPS_PROXY → http_proxy → HTTP_PROXY
```

Минимальная настройка — переменные, установленные на шаге 2.3.

**Постоянная настройка без переменных окружения:** Claude Code читает `~/.claude/settings.json`, где можно задать `env`-блок:

```json
{
  "env": {
    "HTTPS_PROXY": "http://127.0.0.1:10809",
    "HTTP_PROXY":  "http://127.0.0.1:10809",
    "NO_PROXY":    "localhost,127.0.0.1,::1"
  }
}
```

**Критические ограничения:**

| Ограничение | Детали |
| :--- | :--- |
| **SOCKS не поддерживается** | Только `http://` или `https://` |
| **Basic Auth** | Credentials в URL: `http://user:pass@host:port`. Спецсимволы URL-кодируются (`@` → `%40`) |
| **NO_PROXY обязателен** | Должен содержать `localhost` и `127.0.0.1`, иначе OAuth-callback на loopback-адрес уйдёт в прокси и сломается вход |
| **Свой CA** | `NODE_EXTRA_CA_CERTS` (для VLESS-схемы не требуется) |

### 3.3. VS Code

VS Code имеет **два** независимых механизма прокси: собственный `http.proxy` и переменные окружения, которые наследуют дочерние процессы (встроенный терминал, расширения).

**Через настройки** — откройте `settings.json` (`Ctrl+Shift+P` → `Preferences: Open User Settings (JSON)`):

```json
{
  "http.proxy": "http://127.0.0.1:10809",
  "http.proxySupport": "override",
  "http.noProxy": ["localhost", "127.0.0.1"]
}
```

**Через переменные окружения** — если VS Code запущен из терминала с установленными `HTTPS_PROXY` / `HTTP_PROXY`, он и его дочерние процессы унаследуют их. Для расширений, которые сами не читают `http.proxy` (например, некоторые AI-плагины), это единственный способ.

> 💡 **Важно для AI-расширений:** расширения вроде **Continue**, **Cline**, **Roo Code** могут иметь **собственные** настройки прокси. Проверьте настройки конкретного расширения, если запросы не идут.

### 3.4. Cursor IDE

Cursor — форк VS Code, поэтому базовый механизм тот же, но есть **специфическая проблема с HTTP/2**. Cursor использует HTTP/2 для стриминга ответов; некоторые прокси-конфигурации (особенно SOCKS5 без proper HTTP/2-туннелирования) ломают стриминг.

**Симптом:** запрос уходит, но ответ «зависает» или приходит целиком в конце.

**Рекомендуемая конфигурация `settings.json` Cursor:**

```json
{
  "http.proxy": "http://127.0.0.1:10809",
  "http.proxySupport": "override",
  "http.proxyStrictSSL": false,
  "http.noProxy": ["localhost", "127.0.0.1"],
  "cursor.general.disableHttp2": true
}
```

Параметр `cursor.general.disableHttp2: true` **принудительно** переводит Cursor на HTTP/1.1, что резко повышает совместимость с прокси и устраняет «зависающий стриминг».

Если после этого стриминг всё равно нестабилен, попробуйте также:

```json
"cursor.general.disableHttp1SSE": true
```

> 🔄 **Альтернатива:** если `http.proxy` в Cursor ведёт себя нестабильно, используйте **Proxifier** (Windows) с правилом:
> ```
> *.cursor.sh → SOCKS5 127.0.0.1:10808
> ```
> Это обходит встроенный прокси-стек Cursor полностью.

### 3.5. LM Studio

#### Основной сценарий — GUI на ПК

LM Studio для локального инференса **не требует** выхода в интернет через прокси. Он работает с локальными моделями.

> ✅ Если вы не используете LM Studio как удалённый API — **ничего настраивать не нужно**. Просто запускайте GUI как обычно.

#### Сценарий headless на VPS (опционально)

Если вы хотите, чтобы LM Studio отдавал OpenAI-совместимый API с вашего VPS:

```bash
# На VPS (Ubuntu 22.04+)
sudo apt install libfuse2 -y
curl -fsSL https://lmstudio.ai/install.sh | bash
lms bootstrap
lms server start --port 1234 --bind 127.0.0.1
```

> 🔒 **Безопасность:** **никогда** не биндите LM Studio на `0.0.0.0` без аутентификации. Если нужен удалённый доступ — используйте SSH-туннель:
>
> ```bash
> ssh -L 1234:127.0.0.1:1234 pilot@<IP_VPS>
> ```
>
> или reverse-proxy с аутентификацией. `--bind 127.0.0.1` гарантирует, что сервер доступен только с самого VPS.

### 3.6. Gemini CLI

Gemini CLI — Node.js CLI. Читает **стандартные** переменные `HTTPS_PROXY` / `HTTP_PROXY`.

> ✅ Если вы установили их на шаге 2.3 — **ничего дополнительно делать не нужно**.

**Временный прокси только для одного запуска:**

```powershell
# PowerShell
$env:HTTPS_PROXY="http://127.0.0.1:10809"; gemini
```

**Ограничение:** как и Claude Code, Gemini CLI **не поддерживает SOCKS5** — только HTTP/HTTPS. Если ваш клиент даёт только SOCKS, используйте HTTP-порт v2rayN или локальный конвертер.

> 💡 **Свой CA:** Gemini CLI (Node.js) использует `NODE_USE_SYSTEM_CA=1` и `NODE_EXTRA_CA_CERTS`. Для VLESS-схемы это не требуется.

### 3.7. Codex CLI

Codex CLI написан на **Rust** (runtime: `reqwest`) и имеет **отличия** от Node.js-инструментов:

| Параметр | Значение |
| :--- | :--- |
| **Прокси** | `HTTPS_PROXY` / `HTTP_PROXY` (как обычно) |
| **CA-сертификаты** | `CODEX_CA_CERTIFICATE`, с fallback на `SSL_CERT_FILE` |
| **SOCKS5** | ❌ не поддерживается — только HTTP/HTTPS |

**Постоянная настройка:** Codex CLI читает `.env`-файл в корне проекта или в `~/.codex/`. Создайте `~/.codex/.env`:

```env
HTTP_PROXY=http://127.0.0.1:10809
HTTPS_PROXY=http://127.0.0.1:10809
```

Это избавит от необходимости выставлять переменные в каждом терминале.

## 📜 Финальный чек-лист консистентности

Перед первым входом в Claude проверьте **все** пункты:

| № | Проверка | Где проверить | ✅ |
| :--- | :--- | :--- | :---: |
| 1 | IP в браузере = IP VPS | `ipleak.net` в Dolphin-профиле | ☐ |
| 2 | Timezone браузера соответствует стране IP | `browserleaks.com/javascript` | ☐ |
| 3 | Language браузера соответствует стране IP | `browserleaks.com/javascript` | ☐ |
| 4 | WebRTC не показывает из вашей страны IP | `browserleaks.com/webrtc` | ☐ |
| 5 | DNS не из вашей страны | `ipleak.net` → DNS | ☐ |
| 6 | `curl -x http://127.0.0.1:10809 https://api.anthropic.com` соединяется | терминал | ☐ |
| 7 | Claude Code видит прокси (`claude` запускается без ошибок сети) | терминал | ☐ |
| 8 | Cursor с `disableHttp2: true` стримит ответы | Cursor | ☐ |
| 9 | Fraud Score IP не вырос с момента аренды | `scamalytics.com` | ☐ |

> ⚠️ **Главное правило:** одна страна во всём — IP, timezone, language, браузерный профиль. Любое расхождение (например, из вашей страны timezone при американском IP) — самый сильный сигнал для антифрода, сильнее самого IP-адреса.
